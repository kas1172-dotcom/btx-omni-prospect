# Contributing to BTX Omni Prospect

Keep changes focused on the governed POC and its canonical contracts. Do not
introduce duplicate route families, sample fallbacks for connected data, or
autonomous external writes.

Before opening a pull request, run the relevant checks from the root README and
describe the user-visible or contract-level impact. Include tests for behavior
changes and keep source/evidence states explicit.

Use a small, reviewable pull request. Never commit credentials, production data,
or local environment files.
