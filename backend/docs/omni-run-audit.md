# Omni run receipts

`BTX_OMNI_RUN_AUDIT_1` records a request hash before provider work and an immutable final receipt after the read-only Omni service returns. Migration `0032_omni_run_receipts` is additive. A short completion transaction never spans a provider call. Failed storage admission prevents starting a model call; missing completion remains outcome-unknown, never successful.

The receipt binds the returned answer to source revision, bounded completed-read checksums/evidence IDs, graph/market references, build declaration, provider/model and actual provider-usage receipts where available. It is **not** a correctness grade or proof that an external action occurred. `ANSWER_RECORDED` includes deterministic fallback answers, with provider status retained. Omni currently performs no work, preference or external writes during an answer; approved UI workflows remain separate.

GET `/api/omni/runs/{id}` requires the originating authenticated principal, including against managers. Responses are private/no-store. It does not expose raw questions, prior turns, retrieved private memory or model reasoning. The final seller-visible answer is retained as a private operational record; it may contain commercial information. Existing `assistant_turns` is an unused legacy conversation-output table without actor scope, run status or tool audit; historical rows are preserved and never reassigned or exposed by this endpoint. The new receipt owner is not a second conversation or retrieval service.

A RUNNING receipt older than five minutes is displayed as `INTERRUPTED_OUTCOME_UNKNOWN`. This does not cancel the server operation or restart it. Retrying inspection does not repeat model work. Request replay/resumption and automatic retention cleanup are not implemented; production retention policy still needs an explicit operator decision before expansion beyond the SAMPLE POC. Do not infer successful execution from absent receipts. Preserve additive schema on compatible code rollback; destructive downgrade is rejected.
