# Commercial record context

`BTX_GRAPH_RECORD_REFERENCES_1` extends the existing graph facade over the imported
commercial ledger. No graph database, score family or duplicate transaction store
is added. An explicit allowlist links source foreign-key fields to canonical
accounts, programs, components, BUs, facilities, role targets and other records.
Exact assertion IDs depend on account, source record, field and target. Parallel
predicates remain distinct; identical replay yields the same IDs. Each assertion
retains its underlying record, lineage, original direction and derivation version.

These are context-only predicates. They are absent from the permitted commercial
route templates and cannot raise bottleneck strength, evidence support or utility.
Interactions link only their explicit role targets and referenced records. This
does not attach scenario interactions to researched real people or establish warm
access. Account-level quote references never establish program participation.

The optional “Show linked commercial records as context” control changes bounded
neighborhood selection only. The complete selected route stays pinned; route
rankings and factors stay identical. With record context explicitly selected,
record links receive viewport priority over unselected contextual route edges so
mobile users can see a record without first paging past all route alternatives.
Paging and hidden counts remain separate from search completeness. The text
assertion list and evidence inspector use the same canonical edges as the SVG.

Use actual occurrence dates where the source supplies them. Monthly history is
observable at its month end. Unknown dates stay unknown; undated context is not
shown in a historical query before the scenario's declared as-of date. This is a
conservative visibility boundary, not a fabricated publication or employment date.
Past experience remains separate from current feasibility and certificate validity.

Unresolved explicit references are reported, not merged by name or silently
invented. Conflicting cross-account ownership fails projection. Scope/permission
and temporal gates also apply to context expansion and supporting-record fetches.
The facade still requires further qualification of governed capabilities, public
site/role lineage and the legacy relationship presentation; this unit alone is
not a full R5 or hosted graph acceptance claim.
